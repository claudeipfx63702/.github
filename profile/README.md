<h2>一、实验设计：四个样本，一套脚本，七天</h2>

<p>样本来自四种典型定位：A 主打低价共享池，B 主打静态独享，C 主打双 ISP 冗余，D 主打原生家宽但规模小。为避免地域差异干扰，四家都取美国西岸同一城市。每家买最小可用套餐，配置一致，只跑两件事：每五分钟一次的连通性探活，和每小时一次的接口请求。</p>

<p>探活脚本长这样，把状态码和耗时都记进日志：<code>while true; do curl -x http://user:pass@host:port -o /dev/null -s -w "%{http_code} %{time_total} %{time_starttransfer}\n" https://api.ipify.org >> probe.log; sleep 300; done</code>。七天后一条命令算成功率：<code>awk '$1==200' probe.log | wc -l</code> 除以总行数即可。</p>

<h2>四、宣传和实测的差距出在哪个词上</h2>

<p>差距主要来自三个词的解释权。"节点覆盖两百个国家"说的是有地址，不是每条都能稳定跑满；"可用率百分之九十九"如果不注明统计窗口和探测频率，和你的实际体感可能差一截；"支持即时替换"往往指自助面板能点，但换出来的地址质量和原来一样。看宣传时把这三个词换成一个具体问题：近三十天这条地址的投诉记录是多少。</p>

<h3>为什么平均值会骗人</h3>

<p>七天里 A 的平均延迟看起来只有 380 ms，但 P95 到了 680 ms。平均把晚高峰的长尾抹平了，而你真正难受的时刻正是长尾。所以自测时一定看分位数，别只看平均；服务商给的平均值也一样，能要分位数就要分位数。</p>

<h2>常见问答</h2>

<h3>这类排名能直接照着买吗？</h3>

<p>答：不能。样本、地区、时间和套餐都会影响结果，我的七天数据只说明方法有效。正确用法是拿我的指标口径，用同一套脚本测你候选的两三家，再决定。</p>

<h3>为什么可用率 99% 还是感觉经常断？</h3>

<p>答：99% 按月算是七小时，按天算是十四分钟。如果断在你要用的那十分钟，体感就是百分百不可用。所以要结合探测频率和你的使用时段看，而不是看总数字。</p>

<h3>粘性窗口多久合适？</h3>

<p>答：覆盖你的连续使用时长即可，常见十五到三十分钟。做长文档处理或流式输出，建议要求按会话锁定，或者选地址固定的静态方案。</p>

<h3>自测要跑多久才有参考价值？</h3>

<p>答：至少七天，覆盖一个完整工作周和一次周末。少于三天很难碰到晚高峰和上游维护，结论容易偏乐观。</p>
